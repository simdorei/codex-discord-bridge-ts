## Frozen observation contract

The heartbeat observation window is 90,000 ms starting immediately before actual worker creation, with 15,000 ms bounded cleanup. A timeout or forced termination is incomplete, never a pass; these bounds are not increased after failure. An independent owned Node child reads the exact marker every 25 ms sequentially over stdio. There is no socket, listener, runtime singleton bypass, or installed resident runtime. A fresh private namespace is exclusively owned by the component; this does not establish installed runtime-instance authority.

A = `A`, B = `BB`, C = `é`, serialized with JSON quotes and newline, retain 4, 5 and 5 encoded bytes. A blocked write retains one operation/four bytes/one lease. B and C queue to produce three operations/14 bytes/two waiters/one lease. Cancelling original C removes only C: two operations/nine bytes/one waiter/one lease. These counters remain while A writeAll, flush, markClosed join and owned disposal join remain pending. Original A abort is the primary error after joined cleanup. B subsequently acquires and rejects the closed state before preflight. All counters reach zero. A separate success control proves surviving FIFO B actually reaches writeAll and retains one operation/five bytes before completing.

The heartbeat starts after contention and C cancellation. An actual published marker is independently observed while writeAll is blocked; a later publication while flush is blocked; a later publication while disposal is blocked. After writer joins, a final actual publication is held before its wrapper fulfills. Stop must retain worker custody through this accepted publication and a separately gated actual removal. The owned child observes ENOENT after the actual removal, then receives STOP and joins. The exit channel announces heartbeat. Diagnostics must be empty: a successful worker join alone is insufficient.
