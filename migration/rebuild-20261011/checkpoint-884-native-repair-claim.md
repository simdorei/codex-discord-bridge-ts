## Original authority and database identity

The dedicated owner captures the original StoredIngress before submission and retains the confirmed claimed record privately. Its empty opaque token belongs to that exact owner. It cannot be reconstructed from JSON, copied from another owner, used as a store-private RecoveryClaim, or borrowed by NativeRecoveryOwner. No snapshot-to-RecoveryClaim mint or recovery retry protocol is added.

Repair's existing synchronous preclaim checked read is moved into the dedicated owner rather than duplicated. It retains archive/mapping preflight and captures SQLite's main-database location from the configured path before any claim submission. The ACK must match that original location, request ID, configured path, operation, exact expected post-write record and bounded reply shape. A nonempty crossed location is not accepted. Final borrowed checks use the native DatabaseSync prototype location, preserving the original path's native symlink/parent semantics and refusing another database even when its records are identical or its instance location method is overridden.

The worker opens an existing database without creation or migration, starts one IMMEDIATE transaction and invokes the existing exact claim snapshot leaf. Archive/mapping checks run in the same transaction before claim and after trigger/readback. Exact original state, actor, command, target, phase and complete evidence still control the claim. The existing stored-evidence byte gate and exact readback reject changes or oversized trigger output without committing a claim. No queue cancellation, app restart, model turn or tool RPC is added to the worker.

RecoveryGuard authenticates the native Repair token synchronously through checkIn. The check borrows the caller's active transaction and observes its uncommitted changes; it never opens, commits, rolls back or closes that borrowed transaction. Final archive/mapping checks reuse the existing effect guard. rpcCheck remains a synchronous owned callback at the actual wire boundary after asynchronous preparation. Original Stop origin remains unchanged, including the existing read-only preflight allowance and conservative lease/unknown receipt when a later Stop prevents repair mutation.

## Selection and bounded ownership

The first authentic native Selected epoch is captured once before the claim and is retained afterward. No second capture refreshes proof across the new await. The existing Bridge selection lease excludes same-owner Bridge operations through real worker exit and ACK validation, including cancellation and deadline paths. The same original epoch controls subsequent guard checks, so an away-and-back mutation cannot authorize a later repair. Direct legacy construction retains its existing synchronous Selected checks; the installed native path still requires the shared-owner/no-mixed-writers contract. This does not qualify external or mixed legacy Bridge writers.

The claim uses the existing Control1 slot with zero waiting queue. Path and original record/ACK data are bounded. Cancellation, deadline and close join actual native exit, retaining the selection lease and slot until then. There is no SQLite worker termination, detached operation, synchronous write fallback or retry.

Any submitted result without a complete valid ACK, including a worker ok:false refusal that may have rolled back, permanently barriers the installed claim owner. This intentionally conservative rule does not classify an unstructured refusal as proven NotSent. It blocks both the original and fresh ingress claims on subsequent execute calls; no replacement owner is created per invocation. Pre-submission failures do not create an unknown-outcome barrier. This is an in-process installed-owner barrier, not a new durable cross-restart reconciliation mechanism.
