## Central ownership boundaries

`StoreAuthorityDomain` maintains a private registry keyed by one captured native path spelling. A domain is deliberately uncertified. No alias resolution, inode identity, external-writer exclusion, maintenance exclusion or physical-store ownership is inferred from its key. Independent SQLite writers and path aliases remain outside this in-process accounting guarantee. The JSON BridgeState/Selected epoch remains separate.

Writer registrations and inert reservations have private WeakMap provenance. Every new writer increments the revision and permanently revokes an existing reservation, including when the new operation later fails to start, rolls back, is cancelled before submission, or cannot be cloned. At most one inert reservation can be outstanding per domain. Reservations cannot be consumed as wire proof, and no resident, transport or final-validation path uses them.

Sealing revokes reservations and prevents new reservations. It does not block synchronous store opens or original cleanup/completion work. All such writers continue to be counted. Closing refuses while any registered writer remains. No writer queue, SQLite wait, Atomics.wait, callback handshake or network wait is introduced on the main thread.

The two writable factories, `openExisting` and `openInitialized`, return a privately branded DatabaseSync subclass. Its module-private construction token also rejects attempts to recover the subclass constructor from a returned handle and manufacture a crossed binding. Native DatabaseSync method compatibility is retained. Registration precedes construction and spans catalog work, backup/initialization awaits, returned-handle lifetime, transactions, and close. Only confirmed native closed state releases it. A failed close that leaves the handle open retains ownership; a close exception after native closure releases it. Initialization failure cannot discard an unclosed registration. Symbol.dispose follows the same lifecycle. Reopen acquires a fresh registration and revokes reservations before native open; a connection enrolled in a closed domain cannot reopen. Relative initializing handles refuse reopen if cwd changes their original path binding, without lexically resolving native parent/symlink traversal.

Borrowed `initialize` rejects unbranded or foreign handles whenever its requested path or the handle's original path is enrolled. It also checks the worker-side descriptor for enrolled native work. Existing borrowed compatibility behavior remains when unenrolled.

## Native worker enrollment

All production Worker construction remains in OwnedWorkerSlot. The closed manifest contains 75 distinct modules referenced by 86 literal submission URLs. Forty-two complete modules are conservatively potential writers, including semantic readers that currently open read-write connections. Scheduling classes do not decide whether an operation is a writer. In particular, both Observation slots and Background question preparation are enrolled.

A worker registration is created synchronously before lane acquisition or completion-FIFO waiting. The queued executable URL is captured once before awaiting. Pre-spawn rejection/cancellation releases only an unsubmitted registration. After construction, a ticket survives caller timeout, abort, dropped or duplicate ACK, worker error and delayed exit. Only the actual native exit handler releases it. Existing exactly-one-result-after-exit semantics, scheduling capacities and finite completion FIFOs remain unchanged.

The bounded environment-data side channel carries one module URL, original path or explicit read-only marker, version and four-byte shared liveness word. It is installed only around the synchronous Worker constructor and restored in finally, including clone failure. Business workerData is unchanged; the exact-key standard-claim protocol is exercised successfully. The main owner alone retains the authentic registration. The shared word and descriptor are transport metadata, not independent authority. Enrolled workers reject writable opens from read-only modules, foreign paths, mismatched modules or dead registrations. Unknown worker URLs fail closed while a domain is enrolled.

Even compatibility worker lifetimes are counted for the enrollment boundary, so a domain cannot be installed while unverified native work is already queued or running. Existing main-thread writable handles likewise prevent late enrollment for their path.

Source and emitted coverage check the exact reviewed writer/path-field table, all 75 module URLs, the sole Worker constructor, the central writable subclass, explicit readOnly:true for other SQLite constructors, and the ownership import boundaries. The TypeScript syntax-aware audit rejects protected native import aliases, namespace/default imports, constructor escapes, dynamic native loads, native reexports, module-loader bypasses and raw lifecycle prototype calls. Negative syntax fixtures exercise these rules. Backup destinations retain their separately reviewed exclusive-artifact boundaries; no ATTACH or VACUUM INTO path is introduced.

## Explicit local-root installation

The optional sixth argument to runLocalRuntimeApplication is `{kind:'StoreAuthorityAccountingOnly'}`. The CLI never supplies it. The profile and root/database path pair are passively captured before effects, without invoking accessors, and require the original singleton-root bridge path. A module-private construction token prevents JavaScript callers from manufacturing a PosixRuntimeInstance with a fake listening server; retained accounting must match the exact root database path. Enrollment occurs after authentic PosixRuntimeInstance acquisition and before storage preparation. The singleton retains the domain and refuses release until it closes.

Normal cleanup joins the existing runtime owners before closing accounting and releasing the singleton. Startup cleanup seals accounting, then joins/disposes available owners before closure. If a writer or native owner is still unresolved, accounting and the singleton remain alongside the existing retained runtime owners. This wiring is present, but actual UNIX-root execution is an environment-blocked qualification gate below. No independent-writer or alias qualification is asserted by the profile.
