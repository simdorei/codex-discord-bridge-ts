# Bridge state single-owner conversion: preliminary plan

PLAN ONLY, no candidate applied. Existing user authorization covers continued migration, centralized state and preserved restart/thread isolation; this file records technical prerequisites while767 full regression runs.

Rust BridgeState has one per-instance Mutex spanning load/mutate/save, including reads. Current TS BridgeState synchronous operations are single-event-loop non-interleaving, but native per-call write workers would lose that property and could overwrite unrelated settings/selection. Therefore never offload setSelected, rememberSettings, applyFork independently without one shared owner. Existing readonly offload observes whole atomic files but is not a shared mutation owner.

Required first contract: fixed-path runtime-owned Bridge port, exactly one serialization authority shared by all mutation/read call sites. Use existing global worker budgets. No new pool, unbounded queue, or hidden fallback to sync writes. Decide admission using existing owned-worker policy and document conservative busy refusal. Accepted write result must distinguish confirmed write, confirmed refusal before write, and unknown outcome after timeout/cancel/abnormal exit. Unknown means no retry, no rollback claim and no later operation until prior native execution actually exits. A write that may have renamed before timeout is not safely retryable merely because no acknowledgement arrived.

Do not install a mutable in-memory state cache as file authority: external file changes, missing/corrupt file behavior, BOM/UTF8/Serde number preservation, trim behavior, unknown keys and exact pretty serialization must remain visible. Atomic same-directory temp-create/write/fsync/rename and identity-safe cleanup remain. Parent directory durability, Windows sharing/rename/reparse and cross-process singleton are independent unresolved qualifications.

Before implementation, complete caller closure and owner-lifecycle review and find every BridgeState instance/path construction and prototype-bound call. Selected checks coupled to mutation need compound operation or caller custody proof; simply adding await creates new retarget races. Archive current selected-in-scope clear must not become read-await-write that clears a new unrelated selection. Fork inheritance must preserve source settings and never overwrite existing target. Settings writes following remote app-server effect need unknown-outcome reporting that does not resend remote effect. New/Open/Resume selected writes must preserve original target and mutation ordering. Stop/control selected recheck should not wait behind an unrelated long Bridge operation without explicit budget review.

Initial implementation should be standalone owner foundation with deterministic concurrency/no-lost-update tests and crash/late-result probes, not broad call-site replacement. Integration follows explicit bounded call paths and same owner injection. Do not claim complete native Bridge coverage or operational readiness before all bound synchronous call sites are audited and converted safely.

The listed action-target/thread-selection/settings/new/archive/resume/open/control files have now been read in full. Remaining required reads are their relevant transitive dependencies, OwnedWorkerSlot lifecycle and existing runtime owner construction. No source/test file yet.
