# Selected snapshot epoch foundation, no runtime installation

Full source inspection found synchronous final checks in StopControlWorker, StopActionExecutor and RecoveryGuard. Replacing those callbacks with async filesystem reads would violate their no-await custody contract. Proposed standalone primitive: fresh native selected read followed by an opaque owner-local epoch token; final synchronous check validates token ownership, captured selected identity, unchanged epoch and no active owner operation. Any accepted mutation increments epoch before await, including same-value writes and writes that later become Unknown. No-retry, actual-join and existing Control admission remain769 behavior. Busy rejection before admission does not increment epoch. This conservative invalidation may reject more than Rust's current file reread, but cannot authorize a newly selected unrelated target through an old token.

Token is a private WeakMap capability, not a serializable receipt, cache authority, cross-process writer detector, file identity or restart proof. Only valid while every runtime write shares one owner; unconverted sync writers and independently created owners are not covered. No production call sites will be changed by this foundation. Native snapshot never replaces durable DB/turn/generation custody checks. Before eventual integration, refresh tokens at safe async admission points and preserve the final synchronous critical-section callback. Do not reuse old token after an epoch change, read failure or restart. Whole runtime wiring and external-writer/singleton assumptions must be explicit.
