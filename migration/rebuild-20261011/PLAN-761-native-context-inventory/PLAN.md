# Context inventory native boundary plan

Plan only. Product checkpoint756 remains applied. Candidate760 whole regression is still active; no overlapping reference-worker edits or product application here.

Source context opens Codex store BEFORE either all-thread inventory or single-target mapping resolution. Preserve this error ordering with a native existing-store probe for single-thread branch, then the already native exact target selection. All-thread branch can open and query in one native operation. Forward caller signal through both and original selection recheck after rendering. Do not substitute a new target after await.

All-thread source load_recent_threads(limit) applies SQL LIMIT to ordered active rows (updated_at DESC, id) before decoding. Zero means no SQL limit. Existing complete inventory then JavaScript slice is NOT equivalent: it decodes corrupt out-of-limit rows and can reject for unrelated budget overflow. Add a bounded limited read to CodexThreadStore which measures the EXACT selected SQL subset and decodes that same subset in one readonly transaction. Positive u32 limit is preserved; zero remains unbounded semantically but adapter refuses if actual selected rows exceed4096 or4MiB rather than truncating. Selected query keeps all original optional/default/i64/text decoding, duplicate IDs and tie ordering. No new source/filter predicates. Corrupt later selected row fails whole result; corrupt excluded row is not decoded. Measurement is not a bound on SQLite internal sorting/memory.

Use existing reference-reader shared slot, no new workers/pool or queue. New modes bind operation/path/exact limit and response count to original input. Store probe validates existing file/read-only open but MUST NOT query threads or synthesize migrations, since source open alone does not inspect schema. All-thread reply complete bounded ThreadInfo array with strict i64 and active archivedAt0; output4MiB. Native timeout6s matches existing inventory/exact adapter, not a source timing guarantee. Single probe actual native join before selection, then exact query separately. No transaction covering both target mapping and Codex DB is claimed.

Typed optional ContextStoreReads can preserve direct helper compatibility, but BasicActionDispatcher installs the native implementation for production composition. Context render already uses its own source-equivalent singleton3s bounded reader. Do NOT change its source timeout behavior: timeout may return while read-only OS work continues, with original permit retained until exit; no mutation ownership is released. No opportunistic renderer rewrite in this slice.

Tests: limit1 skips corrupt row2 but limit2 refuses; zero full inventory; original ordering/ties/NULL/default/i64; >4096 selected refuses rather than first4096 success; out-of-limit oversized row ignored; selected byte overflow refuses; missing store no creation; malformed schema probe succeeds then later query fails in correct order; single store error masks mapping; signal pre/midflight, changed target recheck, original Context render text and isolation; reply operation/path/limit/row count/shape mismatch; native slot overlap/actual join; fixed path despite caller changes; ordinary root Context wiring.
