## Original transaction and custody boundaries

The worker performs two separate existing-only transactions in their original order. First, the current catalog is verified in BEGIN IMMEDIATE, the original mapped/unmapped route is checked, expired choices are deleted, and the original choice is inserted and read back before commit. Second, a separate existing connection and BEGIN IMMEDIATE verify the catalog, delete orphan control bindings, insert the original turn/job binding, verify that binding and re-read the original choice, then commit. Failure of the second transaction cannot undo the first commit; it is reported as uncertain partial completion, never as an unsubmitted request.

The compatibility helper retains its original route inference, random-ID generation point, cleanup predicates and initialized-store behavior. The native owner mints its original 24-hex choice ID before submission so a lost ACK retains a concrete reconciliation identity. This ID is not permission to retry, and the worker does not use an upsert or replace the original choice. Exact native readback rejects ignored writes and trigger changes. A binding trigger that deletes or changes the choice rolls back only the binding transaction and leaves the first committed original choice intact.

Cancellation or deadline after submission does not terminate the SQLite worker. The worker has no cancellation check between insertion and binding, so cancellation after the first commit still attempts and joins the original binding. The caller retains its target lease through actual native exit and parent response validation. No result containing Busy/ProBusy buttons is returned until a single exact success acknowledgement is validated after both transactions. Existing truthful error notices remain available; no success notice or Codex control dispatch is added on uncertainty.

Ask and Interview propagate the already-admitted ingress key and original event ID through QueuePromptExecutor. BusyResultProducer captures that passive identity before waiting for the target lock, then retains the original thread, actor/channel IDs, prompt, mapped flag, control eligibility, turn, job and sampled timestamp. The installed writer is shared by those calls. One unresolved original occupies a bounded runtime-local barrier; later Busy creation throws the same bound error without another native write. This does not establish durable cross-restart reconciliation, and the error does not permit automatic replay.

Message and interaction processors already begin execution before invoking this path. Their existing failure cleanup retains the ingress in held processing state, stages an outcome-unknown notice, and does not falsely claim that a possibly committed choice was never executed. Successful ingress delivery retains the existing one-time delivery/deduplication semantics. The prepared-intake path always sets autoQueueWhenBusy=true and does not invoke its Busy fallback; no ingress key is synthesized for that path.

## Native protocol and bounds

One fixed pinned path uses the existing shared Control1 lane, with zero waiting queue. Capacity refusal before submission leaves the owner usable; admitted failure, malformed/crossed ACK, timeout, cancellation or missing ACK enters the uncertainty barrier. A synchronous submission-return failure still discovers and joins an admitted worker. Borrowed owners, caller accessors/proxies, malformed identities, invalid signals and invalid timeouts fail closed.

The request/reply envelopes are bounded to 524288/262144 serialized bytes. Paths are limited to 32768 UTF-8 bytes, identity strings to 16384, and the original prompt to 131072. Actor/channel/event values remain bigint within the nonnegative i64 domain. ACKs bind request ID, path, operation, choice ID, ingress/event/actor/channel identity, exact target/turn/job, flags, original creation/expiry timestamps and a SHA-256 digest of the exact UTF-8 prompt. The expiry remains original now + 1800 seconds. Null and empty control identities remain distinct.

The expired-choice DELETE and orphan-binding DELETE retain their full original predicates; neither is silently truncated or paginated. Their scan/write work may scale with existing stored rows, and SQLite may continue native work after the parent's deadline. Protocol bounds and finite worker capacity are not hard native heap, SQL-work, latency, throughput or performance bounds. Existing-only mode refuses missing files/catalog without creation or repair. The Windows native path remains explicitly unqualified.
